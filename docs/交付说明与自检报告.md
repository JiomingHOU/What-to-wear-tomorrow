## 二、技术选型（全部免费、免注册、无需 key、无后端）

| 库 / 接口 | 版本 | 用途 | 官方文档 |
|---|---|---|---|
| 原生 HTML + CSS + JS（无框架、无构建） | — | 应用本体 | https://developer.mozilla.org/zh-CN/docs/Web |
| localForage | 1.10.0 | 封装 IndexedDB | https://localforage.github.io/localForage/ |
| @imgly/background-removal | 1.5.8 | 浏览器本地抠图 | https://github.com/imgly/background-removal-js |
| Open-Meteo Forecast | v1 | 明日天气 | https://open-meteo.com/en/docs |
| Open-Meteo Geocoding | v1 | 城市搜索（`language=zh`） | https://open-meteo.com/en/docs/geocoding-api |

**为什么选原生 JS 而不是 Vue3 + Vite？**
你要求"选最适合零代码维护者的方案"。Vite 需要 `npm install`、`npm run build`、`dist` 目录，改一行字都要重新构建；原生 JS 一行 `<script>` 就是全部，改完保存刷新即可，部署时直接上传文件夹。代价是代码组织靠约定而不是框架，已经用文件拆分 + 中文注释把它控制在可读范围内。

**这两个 CDN 依赖说明：**
- localForage 和抠图库从 jsDelivr/unpkg 加载（三个镜像依次尝试）。localForage 加载失败会自动用内置的 IndexedDB 封装，功能完整；抠图库加载失败会自动降级成原图。
- 天气必须联网（这是它的本质）。断网时首页会显示上一次缓存的天气并标注"离线缓存"。

**两处数据"不完美"但按你的规则处理了：**

1. 种子里 `scene` 出现了 `职场`（2 条）和 `户外`（2 条），不在应用的 7 个场景里。
   **没有改种子数据**，而是在 `scene.json` 里加了 `场景别名`：`职场→通勤`、`户外→休闲`、`上班→通勤`、`逛街→休闲`、`聚会→约会`、`上课→校园`。这样筛选和复刻都能正常工作，你以后加别名也不用改代码。

   **没有改种子数据**，而是在 `color.json` 里放了 38 色色板 + 别名词典，用"长名优先、命中即抹掉"的规则解析。所以 `"黑白灰"` 能正确解析成黑/白/灰三个中性色，`"米白"` 不会被误拆成"米"+"白"。解析不出来时（比如"流行彩色"），复刻不卡颜色、只按性别和场景匹配。

## 五、手动测试步骤（请按顺序点，约 8 分钟）

### 准备

双击 `启动本地预览.bat`，浏览器打开 `http://localhost:8080/index.html`。
（或用手机 + 部署好的 https 网址，见 `docs/部署说明.md`）

### 步骤 1 · 建两个档案并切换

1. 首次打开应该看到引导页，末尾还有 3 条小字说明。
2. 昵称填「测试妈妈」，性别选女，选城市「重庆」→ 点「开始使用」。
3. 底部出现 5 个 Tab，停在「明天」。
4. 去「我的」→ 点「＋ 新建」，建「测试爸爸」（男，北京）。
5. 点「测试妈妈」那一行 → 应该切回妈妈，并且自动跳回首页。

**算通过**：两个档案都在、能来回切、切换后头像和昵称都变了。

### 步骤 2 · 刷新不丢数据

按 F5 刷新。应该直接进入上次的档案，不用重新建。

### 步骤 3 · 热门穿搭导入

去「借鉴」Tab，顶部副标题应显示 **`热门穿搭 48 条（女 26 / 男 22）`**，
切换男女分段控件，数字应分别变成 26 和 22。

### 步骤 4 · 录入一件衣服（关键一步）

1. 「衣橱」→「＋ 添加」→ 看到平铺+白底+光线+完整入镜 4 条要点和一个示意图。
2. 点「📷 拍照」或「🖼 从相册选」，选一张手机里的大照片（最好是 3MB 以上的）。
3. 出现「照片准备好了」，应看到 **`3.2MB → 260KB`** 这样的对比和一个预览图。
4. 点「自动抠图」→ 有进度条和「跳过抠图」按钮。

## 六、需要你知道的限制

1. **数据在各自的手机里，不是共享的。** 妈妈的手机和爸爸的手机数据完全独立，这是"照片不离开用户手机 + 无后端"的必然结果。想同步只能靠「导出备份 / 导入备份」手动搬。
2. **清理浏览器数据会丢衣橱。** 无痕模式、清缓存、卸载浏览器都会清掉 IndexedDB。建议每月点一次「导出备份」。
3. **抠图首次很慢。** 要下载几十 MB 模型，国内网络可能几分钟。界面一直有「跳过抠图」，绝不会卡住流程。
4. **iOS 桌面图标可能是默认样式。** manifest 用的是 SVG 图标（安卓 Chrome 正常）。想完美就补一张 512×512 PNG，步骤写在部署说明的常见问题里。
5. **改代码后手机需要更新缓存。** 把 `sw.js` 里 `CACHE_NAME` 的 `v1` 改成 `v2` 再上传即可。
6. **场景规则抓不住"短裤"这种单品级禁忌。** 现在靠"风格=运动 → 通勤场景硬排除"这一条规则来挡运动背心短裤；如果你的衣服都被打上「休闲」风格，通勤场景就挡不住短裤。要更细，可以在 `scene.json` 里给场景加 `hard_ban_categories`，或者给衣物加更精确的风格标签。
7. **本品没有做**：登录、支付、社区、虚拟试穿、电商导购、后端服务——按你的要求一律没做。

## 七、如果你想微调规则（不用碰代码）

改 `data/rules/` 下三个 JSON，保存，刷新页面。改错了也不会白屏——读不到时会用内置默认值继续跑，自检页第 8 条会告诉你规则是否成功加载。

常见调法：

| 想达到的效果 | 改哪里 |
|---|---|
| 觉得 22℃ 就该穿长袖 | `temperature.json` 里 `hot` 区间的 `temp_max` 从 28 改成 22，`mild` 的 `temp_min` 从 15 改成 22 |
| 通勤场景太严，连运动鞋都不给 | `scene.json` → `通勤` → 把 `hard_ban_styles` 里的 `运动` 删掉 |
| 想让"上班"也能当场景用 | `scene.json` → `场景别名` 里加 `"上班": "通勤"` |
| 觉得亮色配亮色也没问题 | `color.json` → `scores` → `两个亮色互相撞` 从 -8 改成 0 |
| 想加一个自己常用的颜色 | `color.json` → `palette` 里加一条 `{ "name": "焦糖", "hex": "#B5763A", "family": "棕" }` |
| 想让"穿得少的衣服优先推" | `js/recommend.js` 把 `RC.OPTIONS.useWearCount` 改成 `true`（这是预留接口） |
| 觉得鞋被温度限制得太严 | `temperature.json` → `level_tolerance` 把 `"鞋": 1` 改成 `2` |

## 八、实测中发现并修掉的问题

写完后先用静态走查修了 6 个，之后用 Node + 无头浏览器真跑，又修了 5 个。按严重程度列：

### 运行时真会出错的

| # | 问题 | 现象 | 修法 |
|---|---|---|---|
| 1 | `DB.meta.get` 返回整条记录而不是 `value` | 城市缓存、天气缓存、场景记忆、上次档案全部失效 | 取出 `value` 字段 |
| 2 | `App.state.weather` 从来没被写入 | 搭配台和借鉴区永远按 20℃ 打分，温度提示永不出现 | 首页取到天气后同步到全局 |
| 3 | 切换档案没清各页面的临时状态 | 切到爸爸的档案还能看到妈妈的搭配和天气 | 统一 `resetViewStates()` |
| 4 | `RC.daily` 失败分支漏掉 `tempC` | 界面显示「当前筛选条件：0℃」这种假温度 | 失败结果也带上 `tempC/scene/gender` |
| 5 | 鞋被温度档位硬过滤 | 20℃ 想运动时，薄款运动鞋被排除，凑不齐一套 | 鞋/帽子/配饰放宽 ±1~2 档（`level_tolerance`） |

### 界面/文案上的

| # | 问题 | 修法 |
|---|---|---|
| 6 | `.empty` 类名被空槽位复用 | 空槽位排版错乱（整块 padding 变大）→ 改名 `.is-empty` |
| 7 | `.center` 类名被居中小弹窗复用 | 确认框里所有文字被强制居中 → 改名 `.sheet-center` |
| 8 | 衣橱搜索框每次输入整页重绘 | 手机键盘被反复收起 → 只重绘列表 |
| 9 | 缺件文案重复「缺少适合通勤的适合通勤的…」 | 去掉场景提示里的前缀，并按槽位改写 |
| 10 | 领 chips 里追加「不限」后点它会抛异常 | `setValue` 越界 → 加保护 |
| 11 | 顶部标题栏每次重绘都新增一个滚动监听 | 改成全局只挂一个 |

### 数据/规则上的

| # | 问题 | 修法 |
|---|---|---|
| 12 | 种子里有场景标签「街头」不在 7 个场景内，无法归一 | 在 `场景别名` 里加 `街头 → 休闲`（**没改种子文件**） |
| 13 | localForage 的 3 个 CDN 是串行尝试 | 手机离线时要白等 18 秒 → 改成并行抢，最多 5 秒 |

### 测试脚本自身的问题（不是应用的）

- 用 `--dump-dom` 抓页面时异步还没完成，误判"卡在加载中" → 改用 CDP 真等状态
- 点「上衣」点到了遮罩背后的筛选按钮 → 改成优先在弹层内查找（真人点不到背景）

## 九、怎么在自己电脑上复跑测试

测试脚本放在 `_tests/`（**不在发布目录里，不会被部署**）。

```powershell
# 需要 DSH 自带的 node
pwsh -File _tests\run-all.ps1
```

会依次跑：语法 → JSON → 引擎断言 → 真实浏览器端到端，最后打印「全部检查通过」或失败明细。
以后你（或者以后帮你改代码的人）动过任何东西，跑一遍这个就知道有没有弄坏。

| 文件 | 作用 |
|---|---|
| `_tests/run-all.ps1` | 一键跑全部 |
| `_tests/engine-test.js` | 在 Node 里跑推荐引擎断言 |
| `_tests/browser-cdp.js` | 用 CDP 驱动 Edge/Chrome 真点一遍 |
| `_tests/weather-api.js` | 单独验证 Open-Meteo 接口 |
| `_tests/probe.html` | 数据层探针（测试时临时拷进应用目录，跑完删掉） |
